# Week 07 — Integrated Robot Analytics Suite and End-to-End Validation

This week I integrated three previously developed analytical components into a single robot operations dashboard. The first component was the Week 3 KPI anomaly detector, which evaluates deployment performance and produces traceable alerts with contribution analysis. The second was the Week 5 Aido Rover forecasting module, which compares a trailing-average baseline, Holt smoothing, and expanding-window Ridge regression. The third was the Week 6 Fari enterprise churn and retention analysis, including lifecycle classifications, exploratory risk scores, remaining customer value, and an account manager outreach priority list.

I organized the application into four Streamlit tabs: Operational Overview, Anomaly Investigation, Forecasting, and Churn and Retention Risk. My main design goal was to make the opening tab useful to a nontechnical operations manager. It displays anomaly counts, the next-period patrol coverage forecast, the number of deployments below the proposed 90% service threshold, and the number of Fari customers classified as At-Risk. More technical investigation remains available in the other tabs.

One integration inconsistency appeared while connecting the churn model to the executive summary. I initially referenced a lifecycle output field named `status`, but the Week 6 module actually returns `lifecycle_stage`. That mismatch prevented the summary from calculating At-Risk counts correctly. I fixed the integration layer to use the original module's schema and added tests comparing dashboard summary counts with the source lifecycle data. This showed why interface contracts are as important as testing individual models.

I also added a dedicated end-to-end integration suite that compares dashboard anomaly flags against the original source module, verifies repeatability, checks that forecasts do not use future target dates, and covers missing engagement data, zero-anomaly periods, and zero-renewal scenarios. The core analytics and view logic passed these tests. To keep the project portable, I excluded the platform-specific virtual environment that had been bundled with the earlier dashboard.

A major limitation is that the source dataset is synthetic. Fari contract-event retention is presented as a separate simulation, and the available labels do not support a genuine historical renewal-rate trend. I documented this distinction rather than presenting simulated retention as observed customer behavior. The remaining step for deployment readiness is a browser-based Streamlit smoke test after installing dependencies on the target computer.
